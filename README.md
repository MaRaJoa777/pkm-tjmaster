# 포켓몬 타자 마스터

초등학생이 포켓몬 이름을 입력하며 한글 타자 연습을 할 수 있는 반응형 웹 게임입니다.

- **앱:** `index.html` (HTML/CSS/Vanilla JavaScript, 단일 파일)
- **기획 기준:** 업로드된 `mvp.md`
- **주요 기능:** 트레이너 이름 입력, 포켓몬 이름 낙하, 정답 판정, 점수/레벨/생명력, 게임 종료 결과, TOP 3 / TOP 5 랭킹
- **실행:** `index.html`을 브라우저에서 열거나 GitHub Pages로 배포
- **기기 간 랭킹 공유:** Supabase 설정 후 지원. 설정 전에는 현재 브라우저의 로컬 기록만 사용합니다.

## 1. 실행 방법

1. 저장소의 `index.html`을 브라우저에서 엽니다.
2. 트레이너 이름을 입력하고 **모험 시작하기!**를 누릅니다.
3. 화면에 떨어지는 포켓몬 이름을 정확하게 입력하고 Enter 또는 **잡기!**를 누릅니다.
4. 생명력 5개를 모두 잃으면 최종 점수와 랭킹이 표시됩니다.

인터넷 연결이 필요할 수 있습니다. Tailwind CSS와 Jua 폰트는 CDN에서 불러옵니다.

## 2. MVP 요구사항과 구현 점검

| MVP 항목 | 구현 상태 | 비고 |
|---|---|---|
| 어린이용 밝은 포켓몬 테마, 큰 글씨, 둥근 UI | 구현 | 하늘/초원 배경, 색상별 이름표, Jua 폰트 |
| 트레이너 이름 입력 | 구현 | 공백 이름은 거부하고 이름 길이를 제한 |
| 게임 시작/진행/종료 3단계 화면 | 구현 | 시작, 게임, 게임 종료 화면 전환 |
| 이름표의 무작위 X 위치 및 낙하 | 구현 | 화면 너비를 고려한 위치 설정 |
| Enter로 정답 제출 및 입력창 비우기 | 구현 | 모바일 키보드와 한글 조합 입력도 고려 |
| 정답 +1점, 중복 단어는 더 아래 단어 우선 | 구현 | 화면에 존재하는 동일 이름 중 Y 위치가 가장 큰 항목 선택 |
| 50/100/150점 레벨 상승 | 구현 | 낙하 속도 및 생성 간격 증가 |
| 생명력 5개, 바닥 도달 시 차감 | 구현 | 생명력 소진 시 게임 정지 및 결과 화면 |
| 게임 종료 후 TOP 5, 시작 화면 TOP 3 | 구현 | 점수 내림차순으로 표시 |
| MVP의 `localStorage` 기반 기록 보존 | 구현 | 설정 전에는 이 브라우저의 기록으로 저장 |
| 여러 PC/모바일에서 동일한 랭킹 | 조건부 구현 | 아래 Supabase 프로젝트 설정 및 키 입력이 완료되어야 함 |
| 서버 검증/부정 점수 방지 | 미구현 | 현재 MVP에는 로그인이나 서버 측 게임 검증이 없음 |

### 이전 HTML에서 확인된 문제

1. 랭킹은 메모리의 `gameState.rankings` 배열에만 추가되어 새로고침 후 사라졌습니다.
2. `지우`, `이슬이`, `웅이` 예시 점수가 실제 기록과 구분되지 않았습니다.
3. 화면에 표시되는 랭킹이 다른 브라우저나 기기와 동기화되지 않았습니다.
4. 작은 화면/모바일에서 화면 높이와 입력창 공간이 제한될 수 있었습니다.
5. 게임 결과가 여러 번 저장되거나 게임 종료 루프가 중복 실행되지 않도록 종료 처리를 점검할 필요가 있었습니다.

## 3. 기기 간 랭킹 공유 설정 (Supabase)

**중요:** GitHub 저장소만으로는 공용 데이터베이스가 생기지 않습니다. 현재 `index.html`에는 클라우드 연결 설정값이 빈 문자열이므로, 설정하지 않으면 랭킹은 해당 브라우저의 로컬 기록으로 동작합니다. 모든 PC와 모바일에서 같은 랭킹을 보려면 아래 단계를 한 번 완료해야 합니다.

### 3.1 Supabase 프로젝트 만들기

1. [Supabase](https://supabase.com/)에서 프로젝트를 생성합니다.
2. 프로젝트의 SQL Editor를 엽니다.
3. 아래 SQL을 실행합니다.

```sql
create table if not exists public.scores (
  id bigint generated by default as identity primary key,
  player_name text not null check (char_length(player_name) between 1 and 20),
  score integer not null check (score >= 0 and score <= 100000),
  created_at timestamptz not null default now()
);

alter table public.scores enable row level security;

grant select, insert on public.scores to anon;

drop policy if exists "Public can read scores" on public.scores;
create policy "Public can read scores"
on public.scores for select
to anon
using (true);

drop policy if exists "Public can insert scores" on public.scores;
create policy "Public can insert scores"
on public.scores for insert
to anon
with check (
  char_length(player_name) between 1 and 20
  and score between 0 and 100000
);
```

이 정책은 공개 게임 리더보드용으로 누구나 기록을 읽고 새 점수를 제출할 수 있게 합니다. 따라서 **신뢰할 수 있는 경쟁 랭킹이나 개인정보를 저장하는 용도로 사용하지 마세요.** 로그인, 제출 빈도 제한, 서버 측 검증이 필요한 경우 Edge Function 또는 별도 백엔드를 추가해야 합니다. 브라우저 코드에 `service_role` 키를 절대 넣지 마세요.

### 3.2 브라우저용 설정값 입력

1. Supabase 프로젝트의 **Project URL**과 **anon/publishable key**를 확인합니다.
2. 저장소의 `index.html`에서 아래 두 값을 교체합니다.

```js
const SUPABASE_URL = "https://YOUR_PROJECT.supabase.co";
const SUPABASE_ANON_KEY = "YOUR_SUPABASE_ANON_OR_PUBLISHABLE_KEY";
```

브라우저에 넣는 키는 공개용 anon/publishable 키만 사용합니다. `service_role` 또는 secret 키는 공개 저장소나 프런트엔드에 절대 넣으면 안 됩니다. 실제 프로젝트 값을 넣으면 누구나 저장소에서 해당 키를 볼 수 있다는 점을 이해하고, 반드시 위와 같이 최소 권한의 RLS 정책을 적용하세요.

### 3.3 연결 확인

1. `index.html`을 배포하거나 설정된 파일을 브라우저에서 엽니다.
2. 시작 화면의 상태 문구가 **전체 기기 공유 랭킹**으로 표시되는지 확인합니다.
3. 한 기기에서 게임을 끝내고 점수를 제출합니다.
4. 다른 기기에서 같은 사이트를 새로 열거나 랭킹 새로고침을 누릅니다.
5. 같은 랭킹이 나타나는지 확인합니다.

클라우드 연결에 실패하면 앱은 이 기기의 로컬 저장소로 대체하며 화면에 경고 상태를 표시합니다. 로컬 기록은 자동으로 클라우드 기록과 합쳐지지 않습니다.

## 4. GitHub Pages 배포

1. GitHub 저장소의 **Settings → Pages**를 엽니다.
2. 배포 소스로 **Deploy from a branch**를 선택합니다.
3. Branch는 `main`, 폴더는 `/(root)`로 설정하고 저장합니다.
4. 표시되는 Pages URL에서 게임을 엽니다.

Supabase 설정이 완료되어야 Pages URL로 접속하는 PC와 모바일 사이에서 공용 랭킹이 공유됩니다.

## 5. 테스트 체크리스트

- [ ] 이름을 입력하지 않으면 게임이 시작되지 않는다.
- [ ] PC에서 포켓몬 이름을 맞히면 점수가 1점 증가한다.
- [ ] 같은 이름의 단어가 여러 개면 더 아래에 있는 단어가 제거된다.
- [ ] 50, 100, 150점에서 레벨이 각각 상승한다.
- [ ] 단어가 위험선에 닿으면 생명력이 1 감소한다.
- [ ] 생명력 0에서 게임이 정지하고 결과 화면이 한 번만 표시된다.
- [ ] 결과가 로컬 저장소에 기록되고 새로고침 후 TOP 랭킹에 남는다.
- [ ] Supabase 설정 후 클라우드 저장 상태가 표시된다.
- [ ] Supabase 설정 후 다른 PC/모바일에서도 같은 TOP 3 / TOP 5가 표시된다.
- [ ] 좁은 모바일 화면과 세로 방향에서 버튼/입력창을 사용할 수 있다.
- [ ] 네트워크가 끊겨도 게임이 중단되지 않고 로컬 저장 안내가 표시된다.

## 6. 알려진 제한사항 및 다음 개선 후보

- 클라우드 랭킹은 Supabase 프로젝트 생성과 키 설정을 해야 활성화됩니다.
- 공개 점수판은 익명 제출이 가능하므로 점수 위변조를 완전히 막지 못합니다.
- 로컬에 이미 저장된 기록은 클라우드로 자동 이관되지 않습니다.
- 로그인, 트레이너별 최고 점수 관리, 중복/비정상 기록 필터링, 서버 측 점수 검증은 후속 기능입니다.
- 포켓몬 이름 목록은 게임용 단어 목록이며 공식 게임 데이터베이스와 동기화되지 않습니다.
- 외부 CDN(폰트 및 Tailwind)에 의존하므로 오프라인 완전 지원은 제공하지 않습니다.

## 7. 기술 구성

- HTML5 / CSS
- Vanilla JavaScript
